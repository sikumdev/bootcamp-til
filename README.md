# 부트캠프 TIL

실습 코드(`.py`)에 주석만 달면 학습 노트 사이트가 자동으로 만들어지는 저장소입니다.
`git push` 한 번이면 노트 변환 → 공부 주제 이슈 생성 → 사이트 배포가 자동으로 돕니다.

## 폴더 구조

```
.
├─ docs/                      # 여기 안에서 실습하고 정리합니다
│  ├─ index.md               # 첫 화면 · 진도표
│  ├─ tags.md                # 태그별 모아보기 페이지
│  ├─ javascripts/
│  │  └─ til-click.js        # 코드 줄 클릭 → 설명 표시
│  ├─ stylesheets/
│  │  └─ til.css             # 설명 박스 스타일
│  └─ week01/                # 주차 폴더
│     ├─ python/             #  └ 과목 폴더 (사이드바에서 접힘)
│     │  └─ basics.py        #     실습 코드 (여기만 신경 쓰면 됨)
│     └─ sql/
│        └─ select.py
├─ tools/
│  ├─ py2md.py               # .py → 학습 노트 .md 변환
│  └─ issue_extract.py       # #@@@ → GitHub 이슈 (중복 방지 포함)
├─ .github/workflows/
│  └─ deploy.yml             # push 시 변환·이슈·배포 자동 실행
├─ .vscode/
│  └─ python.code-snippets   # 기호 입력 단축어
├─ mkdocs.yml                # 사이트 설정
├─ preview.sh                # 로컬 미리보기
└─ README.md
```

주차 안에 과목 폴더(`week01/python`, `week01/sql`)를 두면 사이드바에서
접었다 폈다 할 수 있습니다. 지금 보는 노트 경로만 자동으로 펼쳐집니다.

## 가장 중요한 규칙: `.py` 를 고치세요

`.py` 가 원본이고 `.md` 는 자동 생성물입니다. `.md` 를 직접 고쳐서 push 해도
다음 배포 때 `.py` 기준으로 다시 만들어져 **덮어써집니다.**
노트 내용을 바꾸려면 항상 짝이 되는 `.py` 를 고치세요.
(예외: `.py` 없이 `.md` 로만 쓴 노트는 그 `.md` 가 원본이라 그대로 유지됩니다.)

## 주석 기호

실습 `.py` 파일에 아래 기호를 주석으로 달면 노트가 자동으로 만들어집니다.

| 기호 | 뜻 | 노트에서 |
|---|---|---|
| `#==` | 섹션 제목 | `##` 헤딩 |
| `#>` | 설명 | 본문 문단 (여러 줄은 줄바꿈 유지) |
| `#!` | 배운 점 · 막힌 곳 | 노란 박스 (코드 밑, 줄바꿈 유지, 연속 줄은 한 박스로) |
| `#?` | 나중에 볼 것 | 하단 체크박스 |
| `#@@@` | 따로 팔 큰 주제 | GitHub 이슈 |
| `#(1)>` | 코드 줄 강조 + 클릭 설명 | 그 줄 파란 배경, **클릭하면** 밑에 회색 설명 박스 |
| `#(1:5)>` | 여러 줄(위로 5줄) 강조 + 설명 | 지정한 줄 수만큼 파란 배경 |
| `# --8<-- [start]` / `[end]` | 노트에 넣을 코드 구간 | 이 구간 안의 코드만 노트에 나옴 |

`title:` 과 `tags:` 는 파일 어디에 있어도 인식됩니다 (맨 위가 아니어도 됨).
`title:` 이 아예 없으면 아직 안 쓴 파일로 보고 노트를 만들지 않습니다.

## 핵심 규칙 1: 코드는 감싼 구간만 나옵니다

노트에 코드를 넣으려면 `# --8<-- [start]` 와 `# --8<-- [end]` 로 감싸야 합니다.
감싸지 않은 코드는 노트에 나오지 않습니다 (섹션 제목·설명만 남음).
한 파일에서 여러 구간을 뽑을 때만 `[start:이름]` 처럼 이름으로 구분하세요.

## 핵심 규칙 2: 코드 줄 강조 + 클릭 설명

코드 줄 아래에 `#(1)>` 로 설명을 달면, 그 코드 줄이 파란 배경으로 강조되고
**그 줄을 클릭하면** 바로 밑(코드 안쪽)에 회색 설명 박스가 펼쳐집니다 (다시 누르면 접힘).

```python
# --8<-- [start]
def update_post(post_id, post_update, db):
    update_dict = {
        key: value
        for key, value in post_update.model_dump().items()
        if value is not None
    }
    #(1:5)> 실제로 보낸(None이 아닌) 필드만 골라 수정
    #(1)> 1) model_dump()로 요청을 dict로 변환
    #(1)> 2) .items()로 (key, value) 쌍을 꺼냄

    for key, value in update_dict.items():
        setattr(post, key, value)
    return post
# --8<-- [end]
```

- `#(1)>` 는 바로 위 한 줄, `#(1:5)>` 는 위로 5줄을 강조합니다.
- 한 블록에 강조가 여러 곳이면 **번호를 다르게** 주세요. 첫 그룹 `1`, 둘째 그룹 `2` …
  같은 그룹의 여러 줄은 번호를 유지합니다 (범위는 첫 줄이 정함).
- 설명 여러 줄은 줄바꿈이 유지됩니다.
- 설명에 `*` `_` 같은 특수문자를 쓸 땐 백틱으로 감싸세요. 예: `` `def f(*a)` ``

## 태그로 주제별 모아보기

`tags:` 에 적은 태그는 사이트에서 클릭할 수 있습니다. 주차(폴더)가 달라도
같은 태그를 달면 한 화면에 모입니다.

```python
"""
title: 게시글 CRUD
tags: [python, fastapi, 1주차]
"""
```

- 노트 제목 아래 태그를 누르면 같은 태그 노트가 모입니다.
- 사이드바 **태그별 모아보기**(`docs/tags.md`)에서 전체 태그 목록을 봅니다.
- 소문자로 통일하는 등 규칙을 정하세요 (`python` 과 `Python` 은 다른 태그).
- 노트당 2~3개면 충분합니다 (보통 "기술 하나 + 주차 하나").

## 사진 · 표 넣기

사진·표가 많은 노트는 `.py` 대신 **`.md` 로 직접** 쓰는 것이 편합니다.
스크립트는 `.py` 만 변환하고 `.md` 는 건드리지 않으므로, 직접 쓴 `.md` 는
그대로 사이트에 나옵니다 (짝이 되는 `.py` 가 없으면 안전).

- **사진** — `.md` 를 열고 스크린샷을 복사한 뒤 붙여넣기(Ctrl/Cmd + V). 이미지가
  옆 `img/` 폴더에 자동 저장되고 경로도 자동 삽입됩니다. (안 되면 "Paste Image" 확장)
- **표** — `.md` 에 마크다운 표를 그대로 씁니다.

## 기호 입력 단축어 (VS Code / Cursor)

`.vscode/python.code-snippets` 덕분에 단축어 + Tab 으로 기호를 넣을 수 있습니다.

| 단축어 | 나오는 것 |
|---|---|
| `til` | 파일 전체 기본 틀 (title, tags, 섹션, 코드 구간) |
| `sec` | `#== ` (섹션 제목) |
| `desc` | `#> ` (설명) |
| `stuck` | `#! ` (배운 점·막힌 곳) |
| `todo` | `#? ` (나중에 볼 것) |
| `issue` | `#@@@ ` (공부 주제 → 이슈) |
| `fold` | `#(1)> ` (한 줄 강조 + 설명) |
| `foldn` | `#(1:5)> ` (여러 줄 강조, 줄 수 입력) |
| `snip` | `# --8<-- [start]` / `[end]` (코드 구간) |

`til` 은 파일 시작, `snip` 은 섹션 추가할 때. 여러 줄 설명은 첫 줄만 `foldn`, 나머지는 `fold`.

## 처음 세팅 (한 번만)

1. GitHub에 **public** 저장소를 만들고 이 파일들을 올립니다.
2. `mkdocs.yml` 의 `site_url`, `repo_url` 을 본인 주소로 바꿉니다.
3. **Settings → Actions → General → Workflow permissions** 를
   **Read and write permissions** 로 (배포·이슈 생성에 필요).
4. 첫 push 후 워크플로우가 성공하면 `gh-pages` 브랜치가 생깁니다.
   **Settings → Pages → Source** 를 `gh-pages` / `/ (root)` 로 지정.
5. **Issues → Labels** 에서 `til-todo` 라벨 생성.
6. 로컬에 설치: `pip install mkdocs-material`

> 워크플로우 파일을 HTTPS 토큰으로 push 하려면 토큰에 `workflow` 권한이 필요합니다.
> SSH 로 클론했다면 이 제약이 없습니다.

## 로컬 미리보기

저장소 최상단에서:

```bash
./preview.sh
```

브라우저에서 터미널에 뜨는 주소로 접속. 끌 때는 `Ctrl + C`.
처음 한 번은 `chmod +x preview.sh` 가 필요할 수 있습니다.

> `.py` 를 고쳤을 때는 `Ctrl + C` 로 끄고 `./preview.sh` 를 다시 실행해야 반영됩니다.
> (`mkdocs serve` 는 `.md` 변화만 자동 감지합니다.)

## 매일 하는 일

1. `docs/주차/과목/` 안에서 `.py` 로 실습하며 주석으로 정리
   (노트에 넣을 코드는 `--8<--` 로 감싸기)
2. 미리보기: `./preview.sh`
3. `git add . && git commit -m "1주차 python 기초" && git push`

push하면 나머지(노트 변환·이슈 생성·사이트 배포)는 자동입니다.

## 주의

- 노트 수정은 `.md` 가 아니라 `.py` 에서. `.md` 는 자동 생성물이라 덮어써집니다.
- `#@@@` 는 정말 따로 팔 큰 주제에만. 자잘한 건 `#?` 로.
- 코드 줄 클릭·태그·사이드바 접기는 브라우저에서 동작합니다.
  `./preview.sh` 나 실제 배포 사이트에서 확인하세요 (정적 파일 아님).
- 코드를 복사하면 펼쳐 둔 설명 텍스트가 딸려올 수 있습니다 (코드 안 삽입 방식의 특성).
