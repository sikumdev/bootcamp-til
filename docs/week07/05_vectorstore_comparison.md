# 벡터 저장소 — FAISS, Chroma, Pinecone 비교

> 원본 코드: [`05_vectorstore_comparison.py`](05_vectorstore_comparison.py)

## 벡터 저장소는 뭐가 다른가

일반 DB는 "정확 일치"를 잘하고, 벡터 저장소는 "최근접 검색"을 잘함.
임베딩만 만들어서 메모리에 두면 끄는 순간 사라지니까, 보관 + 빠른 검색을 같이 해주는 창고가 필요함.

**일반 DB 질문 예시 — 정확 일치**
- "id가 3인 행을 달라"
- "이름이 김철수인 고객"

**벡터 저장소 질문 예시 — 최근접 검색**
- "이 벡터와 가장 가까운 벡터들을 달라"

!!! warning "질문의 종류가 다르다"
    일반 DB는 "같은 것"을 찾고, 벡터 저장소는 "비슷한 것"을 찾음.

## FAISS

### Flat 인덱스 (완전탐색)

!!! success "FAISS는 DB가 아니라 검색 라이브러리"
    메타데이터·저장 형식은 안 챙겨주고 검색 알고리즘만 제공함.
    Flat은 브루트포스라서 100% 정확하지만, 벡터 개수만큼 전부 비교함.

### IVF / HNSW 인덱스 (근사 검색)

!!! success "지름길(인덱스)로 속도와 정확도를 맞바꿈"
    벡터 1억 개면 질문 1번에 1억 번 비교해야 해서 Flat으로는 못 씀. 그래서 지름길(인덱스)이 필요함.

    - **IVF**: 공간을 구역(클러스터)으로 나눠서 가까운 구역만 뒤짐
    - **HNSW**: 벡터들을 그래프로 이어서 다리를 타고 건너뜀

    둘 다 "전부 안 보는 대신 정확도를 살짝 양보"하는 근사(Approximate) 검색임.

### 저장하고 다시 불러오기

!!! success "순정 FAISS엔 저장 기능이 없다"
    FAISS 자체(순정 라이브러리)엔 메타데이터·자동 영속화가 없어서 저장/로드를 직접 챙겨야 함.
    LangChain으로 감싸서 쓰면 `save_local()` / `load_local()`이라는 편의 함수가 생기는데, 이건 LangChain 쪽 API이지 순정 FAISS 함수가 아님.

## Chroma

### 영속화 (껐다 켜도 남는 색인)

!!! success "경로만 지정하면 디스크에 남는다"
    인메모리로만 두면 노트북을 끄는 순간 색인이 사라져서 매번 재색인해야 함.
    `persist_directory`(경로)를 지정해서 만들면 디스크에 저장되고, 나중엔 같은 경로로 다시 "연결"만 하면 됨.

### 메타데이터 필터 & 문서 관리

!!! success "조건 검색으로 먼저 좁히고, 그다음 의미 검색"
    `where` 조건으로 서랍 안에서 먼저 후보를 좁힌 다음, 그 안에서만 최근접 검색을 함 (의미 검색 x 조건 검색).
    문서는 계속 바뀌니까 전체 재색인이 아니라 `add()` / `delete()`로 증분 관리하는 게 기본임.

### `from_documents`가 실제로 하는 일 (LangChain)

!!! success "한 줄에 임베딩·저장·색인이 다 들어있다"
    ```python
    Chroma.from_documents(docs, embedding, ...)
    ```

    한 줄 안에서 다음 3단계가 자동으로 돌아감:

    1. 전부 임베딩
    2. 벡터 + 원문 + 메타데이터 함께 저장
    3. 검색 준비 완료

## 셋 중 뭘 고를까 — 성능 순위가 아니라 운영 방식으로 고름

FAISS = 칼날(알고리즘 라이브러리), Chroma = 바로 쓰는 로컬 벡터 DB, Pinecone = 운영까지 맡기는 관리형 서비스.

| 항목 | FAISS | Chroma | Pinecone |
|---|---|---|---|
| 정체 | 벡터 검색 라이브러리 | 로컬 벡터 DB | 관리형 클라우드 벡터 DB |
| 실행 위치 | 로컬 CPU/GPU | 로컬/자체 서버 | 클라우드 |
| 영속화 | `write_index`/`read_index` (LangChain 래퍼는 `save_local`/`load_local`) | `persist_directory` 경로 지정 | 서비스에서 관리 |
| 메타데이터 | 직접 구현 필요 | 1급 기능 (`where` 필터) | 지원 (필터, 하이브리드 검색) |
| 비용 | 무료 오픈소스 | 무료 오픈소스 | 무료 Starter, 확장 시 유료 |
| 준비 사항 | 로컬 패키지 | 로컬 패키지 | 계정, API 키, 인터넷 |
| 적합 상황 | 로컬 고속 검색, 직접 튜닝 | 학습·프로토타입·중소규모 | 운영 자동화, 확장, 가용성 |

!!! warning "Pinecone = 항상 최고가 아니라 운영을 넘기는 선택"
    Pinecone이 항상 제일 빠르거나 정확한 게 아니라는 게 포인트임. 같은 조건에서 반복 검증하려면
    오히려 로컬에서 도는 Chroma/FAISS가 낫고, Pinecone은 "인프라 운영을 넘기느냐 마느냐"의 선택임.
