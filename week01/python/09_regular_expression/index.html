    정규식¶

    원본 코드: 09_regular_expression.py

    정규식이 뭐냐¶

    글자를 찾는 게 아니라 규칙을 찾는 것.

    import re

text = "주문번호: 2026"

re.sub("2026", "번호", text)     # "2026" 이라는 글자를 찾음
re.sub(r"\d+", "번호", text)     # "숫자가 1개 이상 붙은 덩어리" 를 찾음

    Warning

    re.sub(패턴, 바꿀것, 대상문자열) 순서.
    첫 인자가 "찾을 글자" 가 아니라 찾을 규칙 이라는 게 핵심.
    규칙으로 찾을 수 있으니 값이 바뀌어도 코드를 안 고쳐도 됨. → 정규식을 쓰는 이유

    항상 r"..." 를 붙일 것¶

    raw string. 백슬래시를 글자 그대로 넘기라는 표시.

    "\\d+"    # 됨. 근데 백슬래시를 두 번 써야 함
r"\d+"    # 됨. 쓴 그대로 전달됨

"\\d+\\.\\d+"    # 읽기 힘듦
r"\d+\.\d+"      # 같은 뜻인데 훨씬 명확

    Warning

    파이썬 문자열에서 \ 는 특수문자임 (\n 줄바꿈, \t 탭).
    그래서 "\\d" 처럼 두 번 써야 파이썬이 "진짜 백슬래시 하나" 로 만들어 줌.
    r"..." 는 그 해석을 아예 꺼버림.
    결론 → 정규식 쓸 때는 무조건 r"...". 습관으로 굳혀둘 것.

    구조 — 세 개의 층¶

    정규식이 헷갈리는 이유는 성격이 다른 기호가 섞여 있어서임. 나눠서 보면 잡힘.

     층 ① 칸    — "뭐가 오나"    \d  \s  \w  .  [abc]  그리고 평범한 글자
 층 ② 반복  — "몇 번 오나"   *  +  ?  {n}      ← 바로 앞 칸에만 붙음
 층 ③ 위치  — "어디인가"     ^  $  \b          ← 글자를 안 잡음

    Warning

    패턴은 왼쪽에서 오른쪽으로 칸을 하나씩 만듦.
    각 칸에 "몇 번?" 을 붙이는 게 반복 기호.
    위치 기호는 칸이 아님. 글자를 잡는 게 아니라 자리만 가리킴.

       ^  [A-Za-z]  +  \s  *
   │  └──┬───┘  │  │   │
   │   알파벳    1개↑ 공백 0개↑
   └─ 맨 앞부터

   → "맨 앞부터 / 알파벳이 1개 이상 / 그 뒤에 공백이 0개 이상"

   <  [^>]  *  >
   │   │    │  └─ '>' 글자
   │   │    └──── 0개 이상
   │   └───────── '>' 가 아닌 글자
   └───────────── '<' 글자

   → "< 하나 / > 아닌 게 0개 이상 / > 하나"

    층 ① 칸을 채우는 기호¶

    백슬래시() 임

     기호        의미                          같은 표현
 \d         숫자 한 글자                    [0-9]
 \D         숫자가 아닌 한 글자              [^0-9]
 \s         공백 한 글자 (스페이스·탭·줄바꿈)  [ \t\n]
 \S         공백이 아닌 한 글자
 \w         알파벳·숫자·밑줄 한 글자          [A-Za-z0-9_]
 \W         \w 가 아닌 한 글자
 .          아무 글자 한 개 (줄바꿈 제외)
 a  <  가    평범한 글자는 그 자체

    Warning

    대문자 버전(\D \S \W)은 소문자의 반대.
    re.sub(r"\d", "#", "A1B2") → 'A#B#'
    re.sub(r"\D", "#", "A1B2") → '#1#2'
    . 은 줄바꿈만 예외임.

    층 ① 직접 만드는 칸 — 대괄호 [ ]¶

     [abc]        a 또는 b 또는 c 중 한 글자
 [a-z]        a부터 z까지 중 한 글자 ( - 는 범위)
 [A-Za-z0-9]  범위를 여러 개 이어붙이기
 [^abc]       a, b, c 가 아닌 한 글자
 [.,!]        대괄호 안에서는 특수기호도 그냥 글자

re.sub(r"[aeiou]", "*", "banana")      # 'b*n*n*'
re.sub(r"[^aeiou]", "*", "banana")     # '*a*a*a'
re.sub(r"[.,!]", "", "안녕, 반가워!")    # '안녕 반가워'

    Warning

    ★ ^ 는 위치에 따라 뜻이 완전히 달라짐.
    대괄호 밖 → 문자열 시작. ^SQL
    대괄호 안 맨 앞 → 부정. [^>]

    층 ② 반복 기호¶

    바로 앞의 한 칸에 달라붙음. 혼자서는 못 씀.

     *      0개 이상       \s*      → 공백 있어도 없어도
 +      1개 이상       \d+      → 숫자 최소 하나
 ?      0개 또는 1개    colou?r  → color, colour 둘 다
 {3}    정확히 3개     \d{3}    → 숫자 3자리
 {2,4}  2개 ~ 4개
 {2,}   2개 이상
re.sub(r"\s+", " ", "a   b")   # 'a b'      ← 공백이 반드시 있어야 매칭
re.sub(r"\s*", " ", "a   b")   # ' a  b '   ← 이상하게 나옴
    * 는 0개도 매칭이라 `빈 문자열`까지 잡음
    매칭 위치를 찍어보니 (0,''), (1,' '), (4,''), (5,'')
    글자 사이사이마다 빈 매칭이 생겨서 공백이 끼어듦

    Warning

    반대로 "있어도 되고 없어도 되는" 상황엔 * 가 필수임
    re.sub(r"^SQL:\s*", "", "SQL:hello") → 'hello' (공백 없어도 OK)
    re.sub(r"^SQL:\s+", "", "SQL:hello") → 'SQL:hello' (매칭 실패)

    층 ③ 위치 기호¶

     ^    문자열 시작
 $    문자열 끝
 \b   단어 경계

text = "SQL: SELECT * FROM books; SQL:"

re.sub(r"^SQL:\s*", "", text)   # 'SELECT * FROM books; SQL:'   앞의 것만
re.sub(r"\s*SQL:$", "", text)   # 'SQL: SELECT * FROM books;'   뒤의 것만
re.sub(r"^SQL:\s*|\s*SQL:$", "", text)   # 'SELECT * FROM books;'  둘 다

    Warning

    re.sub 은 원래 조건에 맞는 걸 전부 바꿈.

    # \b 가 없으면 concatenate 속의 cat 까지 바뀜
re.sub(r"\bcat\b", "고양이", "cat concatenate")   # '고양이 concatenate'
re.sub(r"cat", "고양이", "cat concatenate")       # '고양이 con고양이enate'

    Warning

    ★ ^ $ 는 "문자열 전체가 이 모양인가" 를 볼 때만 쓸 것.
    문자열 중간에서 여러 개를 찾을 땐 오히려 방해가 됨.

    그 외 기호¶

     |     또는 (A 또는 B)
 \     뒤 기호의 특수 기능 끄기
 ( )   그룹 묶기

re.sub(r"^SQL:\s*|\s*SQL:$", "", text)   # | 로 두 패턴을 한 번에
re.sub(r"3\.14", "X", "3a14")            # '3a14'  ← \ 로 특수 기능 끔
re.sub(r"(ab)+", "X", "ababab")          # 'X'     ← ( ) 로 묶어서 반복

    헷갈렸던 것 ① \ 와 / 는 완전히 다른 문자¶

    r"^[A-Za-z]/s*"   # ❌ 슬래시(/) + 알파벳 s
r"^[A-Za-z]\s*"   # ✅ 백슬래시(\) + s = 공백

    Warning

    \s 일 때만 "공백" 이라는 특수한 뜻을 가짐.
    /s 는 그냥 글자 그대로 슬래시 다음에 s.

    헷갈렸던 것 ② + 를 빠뜨려서 한 글자만 잡힘¶

    제일 자주 겪는 버그.

    text = "Order 주문번호 A-2026!"

# [A-Za-z] 는 딱 한 글자. Order 는 5글자니까 O 만 지워짐
re.sub(r"^[A-Za-z]\s*",  "", text)   # 'rder 주문번호 A-2026!'  

re.sub(r"^[A-Za-z]+\s*", "", text)   # '주문번호 A-2026!'        

re.sub(r"\d",  "번호", "2026")   # '번호번호번호번호'   ← 한 글자씩 4번
re.sub(r"\d+", "번호", "2026")   # '번호'              ← 덩어리로 1번

    Warning

    한 칸짜리 기호(\d \s . [...])를 썼다면 항상 물어볼 것.
    "이거 여러 글자일 수도 있지 않나?"

    헷갈렸던 것 ③ . 의 두 얼굴¶

    re.sub(r".", "X", "a1 가!")     # 'XXXXX'  ← 숫자·한글·공백·느낌표 다 잡음

re.sub(r"3.14", "X", "3a14")    # 'X'     
re.sub(r"3\.14", "X", "3a14")   # '3a14'

    Warning

    . → 아무 글자 한 개
    \. → 마침표 그 자체
    단 대괄호 안에서는 자동으로 기능이 꺼짐 → [.,!] 는 진짜 마침표.

    헷갈렸던 것 ④ a. 처럼 붙어 있으면 칸이 두 개¶

       a  .
   │  └─ 두 번째 칸: 아무 글자 한 개
   └──── 첫 번째 칸: 글자 'a' 그 자체
   → 2글자짜리 덩어리

# at(cat의) · an(and의) · ap(apple의) 세 군데가 매칭됨
re.sub(r"a.", "X", "cat and apple")   # 'cX Xd Xple'
 a.     a 다음에 아무 글자 하나 (2글자)
 a\.    a 다음에 진짜 마침표 ("a." 만)
 .a     아무 글자 하나 다음에 a
 a*     a 가 0개 이상
 a+     a 가 1개 이상

    Warning

    . 은 앞 글자와 무관한 새 칸을 만들고,
    + * 는 바로 앞 칸을 몇 번 반복할지 정함. 역할이 완전히 다름.

    헷갈렸던 것 ⑤ greedy 함정¶

    제일 유명한 버그.

    text = "<b>안녕</b>"

re.sub(r"<.*>",  "", text)   # ''      
re.sub(r"<.*?>", "", text)   # '안녕'

    Warning

    둘 다 직접 확인한 결과임.

     <  b  >  안  녕  <  /  b  >
 0  1  2  3  4  5  6  7  8

 <.*> (greedy)
   ① 0번에서 < 발견
   ② .* 가 일단 끝까지 다 먹음 (1~8번)
   ③ 이제 > 를 찾아야 하는데 남은 게 없음
   ④ 한 글자씩 뱉으며 뒤로 물러남 (백트래킹)
   ⑤ 8번의 > 를 만나서 성공 → 0~8번 전체가 한 덩어리

 <.*?> (lazy)
   ① 0번에서 < 발견
   ② .*? 가 0개부터 시작 (아무것도 안 먹음)
   ③ 다음 글자 b 가 > 인가? 아님
   ④ 마지못해 b 하나만 먹음
   ⑤ 다음 글자 > → <b> 매칭 완료
   ⑥ re.sub 은 계속 찾으므로 </b> 도 같은 방식으로 매칭
              greedy .*        lazy .*?
 시작 자세      일단 다 먹고 본다   일단 안 먹고 본다
 실패하면       하나씩 뱉는다      하나씩 먹는다
 만나는 >      마지막 것         첫 번째 것
 매칭 개수      1개 (통짜)        2개 (태그별)

    헷갈렸던 것 ⑥ *? 를 어떻게 읽어야 하나¶

    ? 는 뜻이 두 개임. 어디에 붙느냐로 결정됨.

        앞에 뭐가 있나                        ? 의 역할
 글자 칸 뒤   a?  \d?  [abc]?          개수 세기 — 0개나 1개
 반복 기호 뒤  *?  +?                  성격 바꾸기 — lazy 로

    Warning

    "개수 기호 다음에 ? 가 왔네? 그럼 개수가 아니라 스위치구나."
    *? +? 는 두 글자로 된 하나의 기호로 통째로 볼 것.
    *? = 게으른 별표 (0개 이상, 최소로)
    +? = 게으른 플러스 (1개 이상, 최소로)

    # 패턴   개수 (안 변함)   성격
  *      0개 이상        최대로
  *?     0개 이상        최소로
  +      1개 이상        최대로
  +?     1개 이상        최소로

# * 이 허용하는 범위:  0 1 2 3 4 5 ... ∞
                     ↑              ↑
   lazy:   여기서 시작해 오른쪽으로 ──────→
   greedy: ←────────── 여기서 시작해 왼쪽으로

    Warning

    ? 를 볼 때 딱 하나만 확인 → "앞에 개수 기호가 있나?"
    있으면 스위치, 없으면 개수.

    ★ 헷갈렸던 것 ⑦ [^>]* 가 lazy 보다 나은 이유¶

    # b 를 먹고, 다음이 > 니까 더 못 먹고 멈춤 → 자연스럽게 <b> 에서 종료
re.sub(r"<[^>]*>", "", "<b>안녕</b>")   # '안녕'

    Warning

    <.*?> → 먹었다가 뱉을 수도 있는 방식
    <[^>]*> → 처음부터 못 먹게 막는 방식
    실무에서는 [^>]* 를 권장.

    헷갈렸던 것 ⑧ ^ $ 를 잘못된 자리에 씀¶

    text = "<b>제목</b><i>설명</i>"

re.sub(r"<[^>]*>", "", text)   # '제목설명'

    헷갈렸던 것 ⑨ 줄바꿈은 따로 처리 안 해도 됨¶

    text = "SELECT   title\nFROM     books"

# \s 가 이미 줄바꿈을 포함함. \n 을 따로 안 잡아도 됨
re.sub(r"\s+", " ", text)    # 'SELECT title FROM books'            

# 실무에서는 strip() 과 함께 쓰는 게 공식
cleaned = re.sub(r"\s+", " ", text).strip()
    + 가 있으면 연달아 붙은 공백류를 한 덩어리로 잡아 한 칸으로 바꿈
    + 가 없으면 한 글자씩 각각 공백 한 칸으로 → 3개는 그대로 3개

    Warning

    위 결과 직접 확인함.

    실전 패턴 모음¶

    # 텍스트 정리
re.sub(r"\s+", " ", text).strip()              # 연속 공백/줄바꿈 → 한 칸
re.sub(r"\s+", "", text)                       # 공백 전부 제거
re.sub(r"<[^>]*>", "", text)                   # HTML 태그 제거
re.sub(r"[^가-힣A-Za-z0-9\s]", "", text)        # 한글·영문·숫자·공백만 남김

# 접두어 / 접미어 제거
re.sub(r"^Order\s*", "", text)                 # 앞의 "Order " 제거
re.sub(r"^[A-Za-z]+\s*", "", text)             # 앞의 영문 단어 하나 제거
re.sub(r"^SQL:\s*|\s*SQL:$", "", text)         # 앞뒤 동시에

# 코드블록 마커 제거
re.sub(r"^```sql\s*|\s*```$", "", raw)         # sql 고정
re.sub(r"^```\w*\s*|\s*```$", "", raw)         # 언어 무관 (python, js 등)
 목적             패턴
 숫자 덩어리        \d+
 소수점 숫자        \d+\.\d+
 한글만           [가-힣]+
 이메일 (간단)      [\w.]+@[\w.]+\.\w+
 전화번호          \d{2,3}-\d{3,4}-\d{4}
 괄호 안 내용       \([^)]*\)

    패턴 만드는 4단계¶

    읽는 건 왼쪽→오른쪽. 쓰는 건 이 순서로.

    # 예: <b> 같은 HTML 태그를 지우고 싶다

 ① 말로 풀기    "< 로 시작해서, 아무거나 오다가, > 로 끝난다"
 ② 칸 나누기    <  /  아무거나  /  >
 ③ 기호로 바꾸기  <  /  [^>]     /  >
 ④ 반복 붙이기   <  /  [^>]*    /  >

 → 완성: r"<[^>]*>"

    Warning

    ③단계에서 "아무거나" 를 . 으로 할지 [^>] 로 할지가 판단 지점임.
    "여기서 멈춰야 할 글자가 정해져 있나?" 를 물어보고, 있으면 [^멈출글자].

    정리¶

    # 정규식 = 칸(뭐가) + 반복(몇번) + 위치(어디)

 칸:    \d  \s  \w  .  [abc]  [^abc]  그리고 평범한 글자
 반복:  *  +  ?  {n}      ← 바로 앞 칸에만 붙음
 성격:  뒤에 ? 하나 더     → lazy
 위치:  ^  $  \b          ← 칸이 아님

    Warning

    읽을 때 → 왼쪽에서 오른쪽으로 한 칸씩.
    쓸 때 → 말로 풀고 / 칸 나누고 / 기호 바꾸고 / 반복 붙이기.
